## 1. 업그레이드 목표 & 성공 지표

### 목표

1. **첫인상**: 랜딩에 들어온 아이가 10초 안에 "게임 같다, 해보고 싶다"고 느낀다.
2. **몰입**: 퀘스트 1개를 끝내면 다음 행동(다음 퀘스트, 미션, 상점, 자랑하기)이 자연스럽게 이어진다.
3. **어디서나**: PC·태블릿·모바일 모두에서 학습할 수 있다. 모바일은 퀴즈형 문제로 진행한다.
4. **성장 경로**: 기초(1단계) → 응용(2단계) → 만들기(3단계)로 이어지는 6개월 이상의 학습 여정을 만든다.
5. **안전**: 아동 개인정보 최소 수집, 과몰입 방지, 조작 불가능한 보상 체계.

### 성공 지표 (출시 후 4주 측정)

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 랜딩 → 로그인 전환율 | 현재 대비 +30% | 분석 도구 퍼널 |
| D1 / D7 재방문율 | 40% / 20% 이상 | 출석 데이터 |
| 세션당 완료 퀘스트 수 | 3개 이상 | `user_progress` |
| 모바일 세션 비율 / 모바일 퀘스트 완료율 | 측정 시작 / 70% 이상 | UA + 퀴즈 완료 로그 |
| 자랑하기(공유) 사용률 | 활성 사용자 15% 이상 | `share_cards` |
| Lighthouse Performance / Accessibility | ≥ 80 / ≥ 90 (모바일 기준) | Lighthouse CI |
| 보상 조작 가능 경로 | 0건 | RLS 테스트 + Supabase Advisors |

## 2. 핵심 설계 결정 (모든 Phase 공통)

> 아래 결정은 이후 모든 Phase에서 기준이 됩니다. 바꾸려면 이 절부터 고칩니다.

### 2.1 용어 체계 (확정: §12-Q1)

현재 UI는 **스테이지**를 "1단계: 파이썬 마을 입구"처럼 부르고 있어, 요구사항의 "1·2·3단계(기초·응용·만들기)"와 이름이 겹칩니다. 그래서 다음 계층을 사용합니다.

```
월드 (World)   : 1월드 기초 · 2월드 응용 · 3월드 만들기   ← 요구사항의 "1·2·3단계"
 └ 스테이지     : 파이썬 마을 입구, 변수의 숲 …           ← 현재 "N단계"를 "스테이지 N"으로 변경
    └ 퀘스트    : 코드 / 퀴즈 / 프로젝트 / 보스
```

### 2.2 데이터 모델 확장 방향

| 대상 | 변경 |
|---|---|
| `worlds` (신규) | `id, order, slug, title, theme, description, unlock_rule jsonb` |
| `stages` | `world_id` FK 추가, `UNIQUE("order")` → `UNIQUE(world_id, "order")` |
| `quests` | `quest_type` (`code` / `project` / `quiz` / `boss`), `quiz_kind` (`multiple_choice` / `fill_blank` / `parsons` / `bug_hunt`), `is_mobile_friendly` |
| `quest_answer_keys` (신규) | 정답, `expected_output`, 힌트, `solution_code`를 **클라이언트가 조회할 수 없는 별도 테이블**로 분리 (service role만 접근) |
| `user_progress` | `stars`(0~3), `best_stars`, `attempts` 추가 |
| `users` | `nickname`, `grade`, `avatar_config jsonb`, `coins`, `settings jsonb`(사운드 등), `last_login_provider` 추가. `total_xp`, `coins`, `golden_keys`는 **클라이언트 UPDATE 금지** |
| `coin_ledger` (신규) | 모든 재화 증감을 기록하는 원장 (`amount, reason, ref_id`). 잔액은 원장에서 계산하고 캐시 |
| `achievements` / `user_achievements` | 기존 `user_badges.badge_type` CHECK 제약을 정의 테이블 FK로 교체해 30종 이상으로 확장 |
| `daily_missions`, `user_daily_missions`, `attendance` | 데일리 미션·출석. 날짜는 **KST(Asia/Seoul)** 기준 |
| `items`, `user_items`, `user_equipped` | 상점·인벤토리·장착 |
| `share_cards` | 자랑하기 카드 (공개 페이지용 최소 정보만 저장) |
| `creations` | 3월드 작품 (코드, 썸네일, 공개 범위, 리액션 수) |

### 2.3 서버 권위(Server-authoritative) 보상

- XP·코인·별·업적·아이템 지급은 **API Route → Postgres 함수(`SECURITY DEFINER`) 한 트랜잭션**으로만 처리합니다. 예: `complete_quest(quest_id, submission)`.
- 같은 퀘스트를 중복으로 완료해도 보상은 한 번만 지급되도록 멱등성을 보장합니다 (유니크 키 + 원장 `ref_id`).
- 퀴즈 정답은 서버에서만 채점합니다. 클라이언트로는 문제와 보기만 내려보냅니다.

### 2.4 콘텐츠를 코드로 관리 (Content as Code)

- 퀘스트를 `content/worlds/<world>/<stage>/<quest>.yaml`(또는 `.ts`)로 작성하고 zod 스키마로 검증합니다.
- `npm run content:build`가 시드 SQL을 생성하거나 Supabase에 업서트합니다. 1,599줄짜리 수작업 SQL에서 벗어납니다.
- CI에서 모든 `solution_code`를 Node용 Pyodide로 실행해 **자기 검증을 통과하는지** 자동으로 확인합니다. 콘텐츠 100개 이상 규모의 품질을 지키는 핵심 장치입니다.

### 2.5 프런트엔드 구조

- 퀘스트 엔진: `useQuestSession`(진행 상태, 저장, 힌트, 보상, 축하 시퀀스) 공통 훅 + 유형별 렌더러(`CodeQuest`, `ProjectQuest`, `QuizQuest`, `BossQuest`).
- 디자인 토큰은 `globals.css`의 `@theme`에 모으고, 컴포넌트에서 색상을 하드코딩하지 않습니다.
- 애니메이션: Framer Motion(UI 전환) + Lottie 또는 Rive(캐릭터, Phase 0 스파이크로 결정) + canvas-confetti(축하). 모든 연출은 `prefers-reduced-motion`과 "저사양 모드"를 지원합니다.
- 사운드: `use-sound`(Howler) 기반 `SoundProvider`. 효과음은 기본 ON, BGM은 기본 OFF.

### 2.6 건강한 재미 원칙 (아동 대상)

- 보상은 **학습 행동**(풀기, 다시 풀기, 힌트 없이 도전, 꾸준함)에만 줍니다.
- **실제 결제 없음, 확률형 뽑기 없음.** 보상 상자는 내용물을 미리 보여주거나 확률을 공개합니다.
- 경쟁보다 **자기 기록과 협력**을 우선합니다. 리더보드는 opt-in으로만 운영합니다.
- 40분 연속 플레이 시 휴식 알림을 띄우고, 밤 시간대 보너스 같은 장치는 두지 않습니다.
- 공개되는 정보는 **닉네임 + 캐릭터 아바타**뿐입니다. 실명, 이메일, 프로필 사진은 노출하지 않습니다.

### 2.7 브랜치 & 릴리즈 전략 (확정: P0-12)

- Phase당 브랜치 1개 `feat/phaseN`(main에서 분기). 작업 항목 1개 = 커밋 1개(제목에 P/B-ID), 항목마다 푸시합니다.
- 계획서 체크박스·상태표·§13 기록은 해당 작업 커밋에서 함께 갱신합니다.
- Phase 종료 시 `main`으로 PR 1개(템플릿: `.github/pull_request_template.md`). 병합은 merge commit(squash 금지)으로 작업별 커밋을 보존합니다.
- 긴급 수정은 `main`에서 `hotfix/<주제>`로 분기하고, 병합 후 진행 중인 Phase 브랜치에 `main`을 반영합니다.
- Phase 2·3은 병행하되 각자 `main`에서 분기합니다. 한쪽이 병합되면 다른 쪽에서 `git merge main`. 계획서 충돌은 양쪽 변경을 모두 살리고 상태표 수치를 다시 셉니다.
- 공유 브랜치 force-push 금지. 마일스톤 태그는 `main` 병합 후 부여합니다: v0.4(P1-24/P3-20) ~ v1.0 (§10 표).
- CI(P1-15)가 생기기 전까지는 PR 전에 lint·tsc·vitest를 로컬에서 실행합니다.

## 3. 제안: 재미 요소 (게이미피케이션 v2)

> 요구사항의 "자랑하기·레벨·코인"을 중심으로, 아이들이 **모으고, 꾸미고, 보여주고, 다시 오게** 만드는 4개 루프로 구성했습니다.

```
 [배우기] 퀘스트 클리어 ──► XP·코인·별 ──► [모으기] 레벨업·업적·스티커 도감
     ▲                                        │
     │                                        ▼
 [다시 오기] 데일리 미션·출석·스트릭 ◄── [꾸미기/자랑하기] 상점·캐릭터·공유 카드
```

| # | 요소 | 내용 | 우선순위 | Phase |
|---|---|---|---|---|
| F1 | **레벨 개편** | Lv 1~50. 1월드 완료 ≈ Lv 10, 2월드 ≈ Lv 20, 3월드 ≈ Lv 30, 이후 데일리·복습으로 Lv 50. 5레벨마다 새 칭호와 보상 | Must | 8 |
| F2 | **코인(파이코인)** | 퀘스트·별·미션·출석·업적으로 획득, 상점에서 사용. XP는 성장 지표(소비 안 함), 코인은 화폐로 역할을 분리 | Must | 8 |
| F3 | **별점 ⭐⭐⭐** | 퀘스트마다 최대 3개. ⭐ 클리어 / ⭐⭐ 힌트 1회 이하 / ⭐⭐⭐ 힌트 0회 + 황금키 미사용 (퀴즈는 첫 시도 정답). **다시 풀어 별을 채우는 복습 동기** | Must | 8 |
| F4 | **데일리 미션 & 출석** | 매일 미션 3개(예: "퀘스트 2개 클리어", "힌트 없이 1개", "오늘의 퀴즈"). 7일 출석 달력(7일째 보물상자). 스트릭 불꽃 + 스트릭 방패 아이템 | Must | 8 |

## 4. 제안: 모바일 친화 문제 유형

> 요구사항의 "객관식"에 더해, **키보드 없이도 코딩 사고력을 기를 수 있는** 4가지 유형을 제안합니다. 모두 서버에서 채점합니다.

| 유형 | 화면 동작 | 기르는 능력 | 예시 |
|---|---|---|---|
| **객관식** `multiple_choice` | 4지선다. 보기 안에 코드 블록 가능 | 코드 읽기, 결과 예측 | "이 코드를 실행하면 무엇이 출력될까요?" |
| **빈칸 채우기** `fill_blank` | 코드의 `___` 자리를 아래 토큰 칩을 탭해서 채우기 | 문법 기억 | `for i in ___(5):` → [`range`] [`len`] [`list`] |
| **코드 순서 맞추기** `parsons` | 섞인 코드 줄을 드래그하거나 탭해서 정렬 (심화: 들여쓰기 단계까지) | 논리 흐름, 들여쓰기 | 구구단 코드 4줄 정렬 |
| **버그 찾기** `bug_hunt` | 틀린 줄을 탭한 뒤 고친 버전을 선택 | 디버깅 | `print("안녕)` 줄 찾기 |

공통 UX:
- 정답을 맞힌 뒤 **"직접 실행해 보기"** 버튼으로 같은 코드를 Pyodide에서 실행합니다. 읽은 코드와 실제 결과를 연결해 줍니다.
- 오답이면 파이뱀이 해설합니다(`quiz_explain` 프롬프트, 폴백은 정적 해설).
- 코드 작성 퀘스트에도 모바일용 **코드 키보드 툴바**(`(` `)` `:` `"` `=` `[` `]` `Tab` `print` 등 자주 쓰는 토큰)를 추가합니다 (Phase 6).

## 6. 제안: 디자인 시안 방향 3가지

> Phase 2에서 시안을 **클릭해 볼 수 있는 인터랙티브 프로토타입**(랜딩 · 월드맵 · 퀘스트, 데스크톱 + 모바일, 대표 모션 포함)으로 만들어 비공개 링크로 공유합니다. 의견을 받아 하나를 고르거나 섞어서 확정한 뒤 구현합니다.
>
> **결정 (2026-11-03, §12-Q7):** **A(모험 섬) 또는 B(마법 그림책)**로 진행하고 C는 제외합니다. Phase 2에서는 A, B 프로토타입과 둘을 섞은 혼합안(A×B)을 함께 보여드립니다. C는 비교 기록용으로 표에 남겨 둡니다.

| | A. 🏝️ 모험 섬 (캐주얼 게임 · 클레이) | B. 📖 마법 그림책 (손그림 · 수채화) | C. 🚀 코딩 우주 탐험 (네온 팝) |
|---|---|---|---|
| 한 줄 | 말랑한 3D 클레이 느낌의 모바일 캐주얼 게임 | 현재의 따뜻한 톤을 고급 그림책으로 발전 | 행성을 탐험하는 우주 모험, 고학년 취향 |
| 컬러 | 비비드 파스텔(민트·코랄·레몬·스카이), 흰 하이라이트 | 크림·올리브·테라코타·물빛 블루, 종이 질감 | 딥 네이비 배경 + 네온 퍼플·시안·옐로 포인트 |
| 타이포 | 제목: Jua / Cafe24 써라운드, 본문: Pretendard | 제목: Gaegu 손글씨, 본문: Gowun Dodum | 제목: Black Han Sans / Do Hyeon, 본문: Pretendard |
| 월드맵 | 바다 위 섬들. 스테이지가 섬 위 건물, 캐릭터가 길을 따라 통통 점프 이동, 구름·파도 패럴랙스 | 펼쳐진 보물지도 두루마리. 잉크로 길이 그려지고 스탬프로 클리어 표시 | 은하 지도. 스테이지 = 행성, 로켓이 궤도를 따라 비행, 별 파티클 |
| 퀘스트 화면 | 게임 대사창 + 큼직한 3D 버튼(꾹 눌리는 피드백) | 책 펼침 레이아웃. 왼쪽은 이야기, 오른쪽은 공책(에디터) | 우주선 조종석 HUD. 에디터는 다크 테마 |
| 시그니처 모션 | 바운스, 젤리 스퀴시, 코인 튀어나옴 | 페이지 넘김, 잉크 번짐, 스탬프 쾅 | 워프, 홀로그램 글리치, 행성 착륙 |
| 장점 | 게임성 최고, 전 연령 직관적, 모바일과 궁합 | 따뜻함, 브랜드 연속성, 학부모 호감 | 고학년(10~12세) 선호, "코딩 = 멋짐" 인상, 다크 에디터와 조화 |
| 리스크 | 3D 느낌 에셋 제작량이 많음 | 고학년 남학생에게 유아적일 수 있음, 역동성 낮음 | 저학년에겐 차가울 수 있음, 장시간 다크 화면 피로 |

**추가 아이디어 (월드별 비주얼 변화):** 월드마다 비주얼을 바꿔 **진행 자체가 보상**이 되게 합니다. 같은 디자인 시스템(버튼, 카드, HUD) 위에서 배경, 지도, BGM만 교체합니다.
- A안: 1월드 초록 섬 → 2월드 바다·하늘 섬 → 3월드 메이커 시티(공방 섬)
- B안: 그림책 1권(숲 마을) → 2권(바다 여행) → 3권(발명가의 공방)
- A×B 혼합안: A의 섬 지도 구조와 게임 버튼에 B의 종이 질감, 손그림 일러스트, 손글씨 제목을 입힘

**공통 적용 사항 (어떤 시안이든)**
- 코드 폰트를 JetBrains Mono → **D2Coding**(한글 포함 고정폭)으로 교체 검토. 코드 안의 한글 문자열 정렬이 깨지는 문제를 해결합니다.
- 캐릭터 3인 역할 정립: **파이뱀**(튜터) · **버그버그**(에러·보스 담당 악당 겸 친구) · **별똥이**(보상·별·코인 안내 요정).
- 터치 타겟 48px 이상, 본문 16px 이상, 대비 WCAG AA.
