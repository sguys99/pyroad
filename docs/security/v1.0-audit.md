- **오류 문구**: 응답에 DB `error.message`를 넣는 라우트 0(로그·Sentry만, `reportServerError`)
- **IDOR**: 사용자 id를 본문·쿼리에서 받는 라우트 0. 남의 글·댓글·작품·카드는 소유자 비교 또는 RPC가 404/403
- **대량 할당**: 본문을 그대로 insert/update하는 곳 0(필드를 골라 씀, 보드 테스트가 `user_id` 위조를 확인)
- **오픈 리다이렉트**: `next`를 읽는 곳은 `auth/callback`·`auth/error` 둘 다 `safeNext`(B23, 단위 테스트). `redirect` 파라미터 없음
- **SSRF**: 서버가 사용자 값으로 만든 주소에 요청하는 곳 0(LLM·Kakao·Naver는 고정 주소, 이미지 최적화에 원격 패턴 없음)
- **CSRF**: 세션 쿠키가 `SameSite=Lax`(@supabase/ssr 기본)라 다른 사이트의 POST·PATCH·DELETE에 쿠키가 안 실림. 상태를 바꾸는 GET 없음(크론은 비밀 필요). Origin 검사는 쿠키 없이도 받는 `analytics`만 — 추가하지 않음(L12)

### 3.5 헤더·비밀·의존성

- **헤더**(로컬 운영 빌드 실측): 페이지 CSP nonce + `strict-dynamic`(랜딩만 `unsafe-inline`), `unsafe-eval` 없음, API는 `default-src 'none'; frame-ancestors 'none'`, 모든 응답 `X-Content-Type-Options`·`X-Frame-Options: DENY`·`Referrer-Policy`·`Permissions-Policy`, `X-Powered-By` 없음, HSTS는 Vercel
- **사용자 마크다운 XSS**: 마크다운으로 그리는 것은 튜터·힌트 답(react-markdown, raw HTML 플러그인 없음 → HTML 무시, `javascript:` 주소 제거)뿐. 게시판·공지·작품 제목은 글자로만 그림. `dangerouslySetInnerHTML`은 고정 스크립트·JSON-LD뿐(움직임 설정 JSON은 `<` 이스케이프)
- **튜터 프롬프트 인젝션**: `solution_code`는 어떤 프롬프트에도 들어가지 않음(자유 질문 답을 거르는 데만 서버에서 씀) → 인젝션으로 정답 코드 유출 불가. 코드 피드백 프롬프트에는 `expected_output`이 들어가 학생 코드 주석으로 끌어낼 수는 있음(L5)
- **학생 본인 API 키**: AES-256-GCM 암호문만(`user_api_keys`, service_role 전용), 응답은 등록 여부·끝 4자리
- **클라이언트 번들**: 새 빌드 `.next/static`에서 JWT는 anon 키 1개뿐(service_role 0), 서버 비밀 env 이름·키 모양(`sk-ant-`·`AIza…`) 0. `SUPABASE_SERVICE_ROLE_KEY`는 `NEXT_PUBLIC_`이 아니라 번들에 들어갈 수 없음(L3)
- **`npm audit --omit=dev`**: B105 뒤 critical 2·high 18 — 모두 이 앱 런타임에 닿지 않거나 메이저 업그레이드 필요(L8)

## 5. 남은 위험

- **운영 Advisors는 직접 보지 못함** — 운영은 대시보드 설정(Auth·네트워크) 경고가 더 나옴. §6 ①
- 운영 DB의 **실제 권한 상태**(legacy 자동 부여, 런북 밖에서 손으로 바꾼 것)는 `test:rls:ci`의 `prod_replay` 재현으로만 확인 — 같은 묶음을 순서대로 적용했다는 가정
- 요청 한도는 모두 **fail-open**(DB 오류 때 통과) — 한도 표가 망가지면 튜터·게시판 남용을 못 막음(Sentry로 알림)
- Vercel Firewall·Supabase Auth 속도 제한 값은 코드 밖이라 확인 못 함
- L6(임의 그림 업로드)·L1(관리자 이메일 폴백)은 결정이 필요한 남은 위험
