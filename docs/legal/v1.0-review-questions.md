# pyRoad v1.0 개인정보·약관 법률 검토 요청 질문

> - 작성: 2026-11-17 (P12-06 자체 점검에서 정리, [점검 결과](v1.0-privacy-audit.md)) · 운영자: 개인 개발자 유기홍
> - 이 문서는 전문가에게 그대로 보낼 수 있게 썼습니다. "현재 구현"은 코드·DB로 확인한 사실이고, 조문은 운영자가 찾아본 것이라 **번호·내용이 틀릴 수 있습니다**("조문 확인 필요"는 확신이 없는 것).
> - 아직 법률 검토를 받은 적이 없습니다. 아래 답에 따라 v1.1에서 고칩니다(보호자 이메일 동의 링크 발송은 v1.1로 미뤄 둠).

## 서비스 개요 (검토자용)

- 초등학생 대상 무료 파이썬 학습 웹 서비스(https://pyroad.vercel.app). 결제·광고 없음. 운영자 = 개인 개발자 1인 = 개인정보 보호책임자.
- 로그인: Google·카카오·네이버 소셜 로그인만. 카카오·네이버는 **이용자 식별자만**, Google은 식별자 + 이메일(이름·사진은 v1.0부터 받자마자 지움).
- 저장: 닉네임, 캐릭터, 학년(선택), 학습 기록, 제출 코드, 게시판 글, 작품(코드·그림·대화 기록), 만 14세 미만 여부(결과만), 동의 기록.
- 공개: 닉네임 + 캐릭터. 이용자가 직접 만든 자랑 카드·보호자 리포트 링크는 링크를 아는 누구나(비로그인), 갤러리는 로그인한 학생에게.
- 수탁·국외 이전: Supabase(미국 법인, DB·인증), Vercel(미국, 호스팅), Google(Gemini API, AI 튜터), Sentry(오류 기록).
- 문서: 처리방침 `/privacy`, 약관 `/terms` (소스 `src/lib/legal/privacy.ts`·`terms.ts`).

## A. 만 14세 미만 법정대리인 동의 (P3-15에서 넘긴 3가지 포함)

**Q1. "함께 있는 보호자" 화면 동의가 법정대리인 동의 확인 방법으로 충분한가요?**
- 현재 구현: 아이가 처음 로그인하면 태어난 해로 만 14세 미만인지 묻고, 미만이면 "보호자와 함께 이 화면에서" 동의 패널을 보여 줌(어른 말투, 처리 항목 요약, 필수 확인 2개, 관계 선택: 엄마·아빠·그 밖). 보호자의 이름·연락처·본인 확인은 받지 않음. 기록은 `method = 'guardian_in_person'`, 일시, 약관·처리방침 버전, 관계. 동의 전에는 학습만 가능(제한 모드), 30일 안에 동의가 없으면 계정 파기.
- 관련 조문: 개인정보 보호법 제22조의2 제1항, 시행령 제17조의2(법정대리인 동의 확인 방법 — 문자·카드·본인인증·전화·우편·이메일 등 열거) — 조문 확인 필요.
- 걱정: 실제로는 아이 혼자 눌러도 구별할 수 없음. 시행령이 정한 "확인 방법"에 해당하지 않을 수 있음. v1.1에 보호자 이메일로 동의 링크를 보내는 방식을 붙일 계획인데, (a) 이메일 링크 클릭만으로 충분한지, (b) 그때 받는 보호자 이메일의 보관 기간, (c) v1.0 기간에 "함께 동의"로 들어온 계정을 v1.1에서 다시 확인해야 하는지 알고 싶습니다.

**Q2. 탈퇴·파기 뒤 동의 기록을 보관해야 하나요?**
- 현재 구현: 동의 기록(`user_agreements`)은 계정 삭제와 함께 즉시 삭제(DB CASCADE). 처리방침 3번 "법정대리인 동의 기록: 회원 탈퇴 시까지".
- 관련 조문: 제21조(파기, 다른 법령에 따른 보존 예외), 제22조의2(동의 입증 책임이 처리자에게 있는지) — 조문 확인 필요.
- 걱정: 분쟁 때 "동의를 받았다"를 입증할 자료가 남지 않음. 반대로 남기면 아동 정보를 탈퇴 뒤에도 보관하는 것. 남긴다면 어떤 항목(일시·방법·버전·익명화한 계정 번호)을 얼마 동안 두는 것이 적절한지.

**Q3. 미동의 계정을 파기할 때 네이버 로그인 연결을 끊지 못하는 것이 문제인가요?**
- 현재 구현: 30일 미동의 파기(자동, 하루 한 번)와 탈퇴는 같은 삭제 경로. 카카오는 관리자 키로 연결 끊기를 요청, 네이버는 토큰을 저장하지 않아 자동 파기 때는 끊을 수 없음(탈퇴 화면에서는 재인증으로 끊음). 우리 DB의 정보는 모두 지움. v1.0 처리방침에 "네이버 연결된 서비스 관리에서 직접 해제" 안내를 추가.
- 관련 조문: 제21조(파기) — 네이버 쪽 "연결 정보"가 우리가 파기할 개인정보에 해당하는지 조문 확인 필요.
- 걱정: 네이버 계정에 "pyRoad와 연결됨"이 남음. 네이버 토큰을 암호화해 보관하면 끊을 수 있지만 그것도 새 수집이라 어느 쪽이 나은지.

**Q4. 태어난 해 자기 신고로 나이를 확인하는 방식이 충분한가요?**
- 현재 구현: 태어난 해(경계 해는 달·생일 지남) 선택, "잘 모르겠어요" = 만 14세 미만으로 봄. 결과만 저장, 한 번 정하면 바꿀 수 없음. 하지만 탈퇴 후 다시 가입하거나 다른 로그인 수단으로 새 계정을 만들면 다르게 답할 수 있음.
- 관련 조문: 제22조의2 제1항(만 14세 미만 여부 확인 의무의 정도) — 조문 확인 필요.
- 걱정: 초등학생 대상 서비스인데 "만 14세 이상"으로 답하면 동의 없이 공개 기능을 쓸 수 있음. 초등학생 대상임이 분명한 서비스라면 **모두를 만 14세 미만으로 보고** 동의를 받아야 하는지.

**Q5. 보호자의 권리 행사(열람·삭제·처리정지·동의 철회)를 어떻게 확인하나요?**
- 현재 구현: 처리방침 11번 — 화면(아이 계정으로 탈퇴·초기화·공유 끄기)과 운영자 이메일. 보호자 연락처를 받지 않으므로, 이메일로 "제 아이 계정을 지워 주세요"가 오면 그 사람이 그 아이의 보호자인지 확인할 수단이 없음. 동의 "철회" 기능은 따로 없음(철회 = 탈퇴로 처리하게 됨).
- 관련 조문: 제35조~제38조, 시행령 제46조(정보주체 또는 대리인 확인) — 조문 확인 필요.
- 걱정: 확인 없이 지우면 남의 아이 계정을 지울 수 있고, 확인을 요구하면 확인할 자료가 없음. 최소한의 확인 절차(예: 아이 계정으로 로그인한 화면에서 요청 코드를 만들어 보호자가 전달) 제안을 받고 싶습니다.

**Q6. 동의·약관 동의가 없는 오래된 계정을 지워야 하나요?**
- 현재 구현: 자동 파기 대상은 "만 14세 미만 + 동의 없음 + 나이 확인 후 30일"뿐. 로그인만 하고 온보딩(약관 동의·나이 확인)을 끝내지 않은 계정, 처리방침이 생기기 전(2026-11-06 이전)에 가입하고 다시 오지 않은 계정은 Auth 정보(Google 이메일)와 학습 기록이 기한 없이 남음. 수는 운영 DB에서 아직 세지 않음.
- 관련 조문: 제15조(수집 근거), 제21조(파기), 제39조의6(1년 미이용자 — 2023 개정으로 삭제된 것으로 알고 있음, 조문 확인 필요).
- 걱정: 수집 근거(동의·약관)가 없는 상태로 보관 중. 일정 기간(예: 30일) 지나면 지우는 것이 맞는지, 기존 사용자에게 먼저 알려야 하는지.

## B. 공개·공유

**Q7. 아이의 학습 성과를 링크로 공개하는 것이 "이용자의 요청에 따른 처리"로 충분한가요?** (P9 개정 때 넘긴 ①)
- 현재 구현: 아이가 직접 "만들기"를 눌러야 자랑 카드(닉네임·캐릭터·레벨·별·업적 수, 90일 공개)와 보호자 리포트(요일별 학습, 만료 없음) 링크가 생김. 링크를 아는 누구나 로그인 없이 봄. 만 14세 미만은 법정대리인 동의를 마친 계정만 만들 수 있음. 별도 동의 체크는 없음.
- 관련 조문: 제15조 제1항 제4호(계약 이행·정보주체 요청에 따른 조치), 제22조의2 — 조문 확인 필요.
- 걱정: 처음 받은 법정대리인 동의 범위에 "공유 링크 공개"가 들어가는지, 공유할 때 따로 보호자 동의가 필요한지.

**Q8. 카카오톡 공유는 이용자 자신의 전송인가요, 우리가 카카오에 제공하는 것인가요?** (P9 ③)
- 현재 구현: 아이가 "카카오톡으로 보내기"를 고르면 브라우저에서 카카오 SDK가 열리고 카드 제목·그림 주소·링크가 카카오로 감. 서버는 카카오에 아무것도 보내지 않음. 처리방침은 "이용자가 카카오톡을 직접 이용하는 것"으로 적음.
- 관련 조문: 제17조(제3자 제공), 제26조(위탁) — 조문 확인 필요.

**Q9. 갤러리에 아동 작품(코드·대화 기록)을 다른 학생에게 공개하는 근거가 충분한가요?**
- 현재 구현: 작품은 기본 비공개, 아이가 "갤러리에 올리기"를 눌러야 로그인 학생에게 공개, 올리기 전 개인정보 자동 검사·본인 확인, 코드는 따로 켜야 보임, 스티커 반응만, 신고 3명이면 숨김. 동의 전 아동은 못 올림.
- 걱정: 대화형 작품의 기록에 아이가 입력한 답(이름 등)이 섞일 수 있음(자동 검사는 전화번호·이메일·긴 숫자 모양만 막음).

## C. 국외 이전·AI 튜터

**Q10. Gemini API 무료 티어에 아동의 코드·질문을 보내는 것 — 약관 위반과 법적 성격**
- 현재 구현: 서버 AI 튜터가 Google Gemini API **무료 티어**로 퀘스트 정보, 학생 코드, 실행 결과, 힌트 단계, 아이가 쓴 질문(개인정보·부적절한 말은 걸러 보냄)을 보냄. 닉네임·이메일·계정 번호는 보내지 않음. 처리방침 7번(위탁)·8번(국외 이전, 공개로 갈음)에 Google을 적고 "무료 이용 조건에 따라 Google이 서비스 개선에 이용할 수 있음"을 알림.
- Google 약관(2026-03-23 시행, 2026-11-17 확인): "18세 미만 대상이거나 이용할 가능성이 높은 서비스에서 쓰지 말 것"(무료·유료 모두), 무료 티어 입력은 Google이 제품 개선·사람 검토에 사용, "무료 티어에 개인정보를 보내지 말 것".
- 관련 조문: 제26조(위탁), 제17조(제3자 제공), 제28조의8(국외 이전) — 조문 확인 필요.
- 걱정: (a) Google이 자기 목적(제품 개선)으로 쓰는 이상 "위탁"이 아니라 "제3자 제공"이어서 별도 동의(아동은 법정대리인)가 필요한지 (b) 약관 위반 상태로 운영하는 계약상 위험. 운영자 쪽 선택지: 출시 때는 서버 튜터를 끄고 저장된 답변만, v1.1에 Anthropic Claude(미성년자 대상 서비스를 안전장치 조건으로 허용)로 전환. 전환할 때 처리방침 변경만으로 되는지, 재동의가 필요한지.

**Q11. 학생이 등록한 본인 API 키 — 키 소유자가 미성년자일 때**
- 현재 구현: 설정에서 Anthropic·OpenAI·Google API 키를 등록하면(암호화 저장) 튜터 요청이 그 회사로 그 키로 감. 처리방침은 "이용자가 선택한 회사로 전송"으로 적음.
- 걱정: 각 회사 API 약관은 계정 소유자 연령(대부분 18세 이상)을 정함 — 아이가 보호자 키를 쓰는 경우의 책임, 이것이 우리의 위탁인지 이용자 자신의 이용인지. 만 14세 미만에게는 이 기능을 막아야 하는지.

**Q12. 국외 이전을 처리방침 공개로 알리는 것으로 충분한가요?**
- 현재 구현: 처리방침 8번에 받는 자·국가·항목·목적·기간을 표로 공개(제28조의8 제1항 제3호 "처리방침 공개" 근거로 적음). 별도 국외 이전 동의는 받지 않음. Supabase 저장 국가는 아직 "확인 후 기재"(운영자가 확인 중).
- 걱정: 아동(법정대리인 동의 대상)에게도 공개로 갈음할 수 있는지, 제3호의 요건(계약 체결·이행에 필요한 처리위탁·보관)에 Gemini 무료 티어가 맞는지.

## D. 보관·기록·고지

**Q13. 접속 기록·로그인 기록의 보관 기간**
- 현재 구현: Supabase Auth가 가입·로그인·탈퇴 기록(IP, Google 이메일)을 우리 DB에 기한 없이 쌓고 있었음(탈퇴한 사람 것도). v1.0에서 DB 저장을 끄고 쌓인 기록을 지울 예정(그 뒤에는 Supabase 로그 플랫폼의 플랜 보관 기간만). Vercel 요청 로그(IP·주소·브라우저 정보)는 Vercel 보관 기간. 보호자 리포트 링크 주소가 Vercel 로그에 경로로 남음.
- 관련 조문: 「개인정보의 안전성 확보조치 기준」 제8조(접속기록 보관·점검 — 개인정보취급자 기준), 통신비밀보호법(로그기록자료) — 조문 확인 필요.
- 걱정: 이용자 로그인 기록을 지워도 되는지, 운영자(개인정보취급자)의 운영 DB 접속 기록은 얼마나 남겨야 하는지(지금 별도 기록 없음).

**Q14. 개인 개발자 운영자의 안전성 확보조치 의무 범위**
- 현재 구현: 운영자 1인, 운영 DB는 읽기 전용 확인, RLS, HTTPS, API 키 암호화. 내부 관리계획 문서는 없음.
- 관련 조문: 제29조, 「개인정보의 안전성 확보조치 기준」 제4조(내부 관리계획, 처리 규모에 따른 예외) — 조문 확인 필요.

**Q15. 처리방침 변경 공지 기간과 "배포일 = 시행일" 관행** (P9 ②)
- 현재 구현: 처리방침 14절은 "시행 7일 전 공지, 수집 항목·목적이 바뀌는 중요한 변경은 30일 전". 실제로는 v0.9부터 개정 안내를 배포 당일 올리고 같은 날 시행(재동의 없음). v1.0 개정도 같은 방식(수집 항목은 줄고 고지는 실제 동작에 맞춤).
- 관련 조문: 제30조, 시행령 제31조(처리방침 변경 공개) — 조문 확인 필요.
- 걱정: 스스로 정한 7일·30일을 지키지 않는 문제. 문구를 고칠지, 관행을 고칠지.

**Q16. 그동안 처리방침에 없던 처리를 사후에 적는 것으로 충분한가요?**
- 현재 구현: v1.0 점검에서 처리방침에 없던 것을 찾아 적음 — Auth 로그인 기록에 Google 이메일이 남는 것, 웹 저장소의 일부 값, 오류 기록의 User-Agent 원문. Sentry로 보호자 리포트 링크 주소가 갈 수 있었던 것은 코드로 막음.
- 걱정: 고지 누락 기간에 대한 조치(공지에 명시, 개별 통지 필요 여부).
