# v1.0 아동 개인정보 자체 점검 (P12-06)

> - 점검일: 2026-11-17 · 기준 코드: `feat/phase12` (B104 뒤) + 이 점검의 B115·B116
> - 사용자 결정(2026-11-16, §12-Q79): **"자체 점검만, 발송은 v1.1"** — 수집 항목·처리방침과 실제 동작의 일치를 코드·DB 기준으로 감사하고, 전문가 법률 검토에 가져갈 질문 목록([v1.0-review-questions.md](v1.0-review-questions.md))을 만든다. "함께 있는 보호자 동의"(`guardian_in_person`)를 유지하고 보호자 이메일 동의 링크 발송은 v1.1로.
> - **법률 전문가 검토는 하지 않았다.** 이 문서의 "맞음/안 맞음"은 *처리방침 문장과 코드·DB 동작이 같은가*에 대한 판단이고, 법적 적합성은 모두 "확인 필요"다.
> - 운영 DB·대시보드는 보지 못했다(읽기 권한 없음). 운영 값이 필요한 곳은 "운영에서 할 일"에 확인 SQL로 남겼다.

## 7. 운영에서 할 일 (사용자, 배포 전·당일)

운영 DB는 SQL Editor에서. ①~④의 읽기 쿼리는 먼저 돌려 수를 확인.

① **마이그레이션** `00059`: `node scripts/release/build-release-sql.mjs --release v1.0-phase12` → `release-sql/v1.0-phase12/1_먼저실행.sql` 붙여넣기. NOTICE `[00059] Google 이름·사진 저장 안 함: 트리거 2개`. 실패하면(권한) 트리거를 만들 수 없는 것이니 알려 주기 — 앱은 영향 없음.

② **이미 저장된 Google 이름·사진 지우기**(① 뒤, 되돌릴 수 없음):

```sql
-- 확인
SELECT count(*) FROM auth.users
 WHERE raw_user_meta_data ?| ARRAY['name','full_name','given_name','family_name','picture','avatar_url'];
SELECT count(*) FROM auth.identities
 WHERE provider = 'google' AND identity_data ?| ARRAY['name','full_name','given_name','family_name','picture','avatar_url'];
-- 정리 (Google identity 가 있는 사용자만. Kakao·Naver 는 원래 이 값이 없음)
BEGIN;
UPDATE auth.identities SET identity_data = identity_data - ARRAY['name','full_name','given_name','family_name','picture','avatar_url']
 WHERE provider = 'google' AND identity_data ?| ARRAY['name','full_name','given_name','family_name','picture','avatar_url'];
UPDATE auth.users u SET raw_user_meta_data = raw_user_meta_data - ARRAY['name','full_name','given_name','family_name','picture','avatar_url']
 WHERE raw_user_meta_data ?| ARRAY['name','full_name','given_name','family_name','picture','avatar_url']
   AND EXISTS (SELECT 1 FROM auth.identities i WHERE i.user_id = u.id AND i.provider = 'google');
COMMIT;
```

③ **Auth 감사 로그**(F2, 배포 전 필수 — 처리방침 3번 "자동 삭제"의 전제): Dashboard → Authentication → Audit Logs → "Disable writing auth audit logs to project database" 켜기(대시보드 로그는 플랜 보관 기간 동안 계속 보임 — 화면 이름은 2026-11-17 Supabase 문서 기준, 확인 필요). 그 뒤:

```sql
       count(*) FILTER (WHERE (payload->>'actor_id')::uuid NOT IN (SELECT id FROM auth.users)) AS deleted_users
  FROM auth.audit_log_entries;
SELECT count(*) FROM auth.flow_state;   -- 교환되지 않은 PKCE 상태 (provider 토큰 칸)
-- 보관 기간을 법률 검토(Q13)로 정하기 전 기본 제안: 모두 지움
```

④ **온보딩·나이 확인 전 계정 수**(F7 → §12-Q81 30일 파기로 결정, 00061 적용 뒤 확인은 [v1.0 런북](../release/v1.0-runbook.md) 2-1 "00059·00060·00061 확인"):

```sql
SELECT count(*) FILTER (WHERE onboarded_at IS NULL) AS not_onboarded,

       count(*) FILTER (WHERE age_band IS NULL AND created_at < now() - interval '30 days') AS age_unknown_30d,

```

- 10번 웹 저장소: 실제 키에 맞춤, 서버로 보내지 않음

**다시 동의 필요 여부(판단, 법률 확인 필요 Q15·Q16)**: 받지 않음. 새로 모으는 항목·새 목적·새 수탁자가 없고, Google 이름·사진은 오히려 저장하지 않게 됐다. 접속 기록의 "로그인 기록(이메일 포함)"은 새 수집이 아니라 이미 하던 처리를 적은 것이다(그동안 처리방침에 없었음 — 사후 고지로 충분한지가 Q16). 앱은 버전이 바뀌어도 재동의 화면이 없음(P9 이후 같은 방식).
