## 4. 점검 결과

모두 PASS (`rehearsal-checks.sql`, 22개 + 스크립트 단계).

**00060 크기 CHECK (B108)**

- 넘는 행이 있으면: NOTICE `[00060] ⚠️ 이미 상한을 넘는 행: 코드 1 · 단계 코드 1 · provider 0 → 해당 CHECK 는 NOT VALID …`, `code`·`steps` 두 제약만 `convalidated = false`, provider는 VALID (SIZE-1)
- ⚠️ **넘는 기존 행은 얼어붙음**: 그 행에서 코드를 줄이지 않는 갱신(자동 저장의 단계만·힌트 기록·완료 RPC의 다시 풀기)이 CHECK 위반 23514 (SIZE-2). 50,000자 이하로 고쳐 쓰는 갱신은 됨(SIZE-3), 정확히 50,000자 행은 그대로 갱신됨(SIZE-4), 새 50,001자·provider 33자는 거부(SIZE-5·6) → 런북 2-1에 정리 SQL과 이유를 적음
- 정리(런북 2-1 SQL 그대로) → `VALIDATE` 3개 → 다시 붙이면 `[00060] 크기 CHECK 3개 (모두 VALID)`
- 넘는 행이 없을 때(정리 뒤 재적용, 규모 시험): `(모두 VALID)`

**00061 파기 대상 (B118)**

- 적용 직후 0 (PURGE-1), **29일 뒤 가정에도 0** — 400일 된 무활동 계정도 적용 시각부터 30일 유예 (PURGE-2)
- **31일 뒤 가정 = 무활동 미완료 8명뿐**: ghost1~3(v0.3 무활동)·left3·left10·left40·left100·noage-empty (PURGE-3). 학습 기록이 있는 v0.3 가입자 5명·나이 확인 전 학습자·게시글만 있는 계정·관리자·온보딩 완료 계정은 없음 (PURGE-4)

| 측정 | 값 |
|---|---|
| v1.0 묶음 적용 (합성 44명, CRLF 붙여넣기 전체) | **39~80ms** (두 번 돌린 8회, 롤백 36~52ms) |

- **잠금**: `ALTER TABLE … ADD CONSTRAINT … CHECK`는 `user_progress`·`users`에 ACCESS EXCLUSIVE를 잡고 **COMMIT까지** 유지(묶음이 한 트랜잭션). 00059 `CREATE TRIGGER`는 `auth.users`·`auth.identities`에 SHARE ROW EXCLUSIVE — 그동안 로그인(GoTrue의 `auth.users` 갱신)·자동 저장·완료가 기다림. 검증 스캔은 행 수에 비례
- **운영 규모 판단**: 운영 사용자 수·`user_progress` 크기는 모르지만(런북 0-3에서 확인), 초등학생 서비스 v0.9 운영 규모가 위 시험(20만 행·251MB)보다 크다는 근거는 없음 → **예상 잠금 1초 미만**, 학생에게는 저장이 잠깐 늦는 정도. 0-3의 `progress_size`가 수백 MB를 넘으면 사용자가 적은 시간에
- 남은 위험: (1) 00059가 운영의 `auth` 표에 트리거를 만들 권한 — 로컬과 같다고 가정(00013 `on_auth_user_created`가 운영에 이미 있어 같은 권한으로 보임), 실패하면 전체가 되돌려지고 런북 2-1 "다르면"으로 (2) 운영에 5만 자 넘는 진행 행이 있으면 그 행이 정리 전까지 얼어붙음(SIZE-2) — 런북 0-3에서 미리 셈

## 8. 한계

- 운영 데이터가 아니라 합성 데이터. 운영에만 있는 모양(예: 아주 오래된 행의 NULL 조합, 운영 GoTrue가 쓴 메타데이터 키)은 시험하지 못함 → 런북 1-3·2-2 스냅샷 비교와 0-3 수 세기로 운영에서 확인
- 별도 스테이징 프로젝트가 없어 Supabase 호스팅 환경(권한·pooler·SQL Editor 동작·Dashboard 백업)은 재현하지 못함. SQL Editor는 "CRLF + 파일 그대로 실행"으로만 흉내
- 운영 Postgres 버전·크기·요금제(백업·PITR 유무)는 모름 — 런북 0-3·1-1에서 사용자가 확인
- 백업 복원은 로컬 컨테이너의 `pg_dump`/`pg_restore` 17로만. 운영 pooler 연결·Windows PowerShell 명령은 실행해 보지 못함
- 옛 앱은 v0.9 태그를 `npm ci`로 그대로 빌드했지만 Vercel이 아닌 로컬 `next start`
