### 00060 확인 (B108)

- [ ] 적용 NOTICE가 `[00060] 크기 CHECK 3개 (모두 VALID)`
- [ ] `⚠️ 이미 상한을 넘는 행 …`·`NOT VALID`가 나왔다면 (읽기 전용으로) 행을 확인하고, 학생에게 필요한 코드인지 본 뒤 정리하고 `VALIDATE`:

```sql
-- 넘는 행 (크기만, 내용은 보지 않음)
select user_id, quest_id, char_length(code_submitted) as code_chars, octet_length(step_submissions::text) as steps_bytes
  from public.user_progress
 where char_length(code_submitted) > 50000 or octet_length(step_submissions::text) > 524288;
select id, char_length(preferred_provider) from public.users where char_length(preferred_provider) > 32;
-- 정리 뒤
alter table public.user_progress validate constraint user_progress_code_submitted_size;
alter table public.user_progress validate constraint user_progress_step_submissions_size;
alter table public.users validate constraint users_preferred_provider_size;
```

- 되돌리기: `supabase/rollback/00060_client_write_size_limits.rollback.sql` (제약만 지움, 잃는 데이터 없음)

### 00061 확인 (B118) — 지우는 기능이라 배포 뒤 첫 크론 전에 수부터

기한 = **max(가입일, 00061 적용 시각) + 30일**이라 적용 뒤 30일 동안은 이 규칙으로 지워지는 계정이 0입니다(배포 날 오래된 계정이 한꺼번에 지워지지 않게). 학습 기록·뱃지·게시글·댓글·공지·작품이 있는 계정(온보딩 도입 전 가입자)은 기한이 지나도 지우지 않고, 관리자(`app_metadata.role = 'admin'`)는 크론이 건너뜁니다.

- [ ] 적용 NOTICE가 `[00061] list_expired_incomplete: service_role 전용, 유예 시작 <적용 시각>`
- [ ] (읽기 전용) 30일 뒤 대상이 될 수와 보호받는 수:

```sql
-- 지금 대상 (적용 직후엔 0이어야 함)
select count(*) from public.list_expired_incomplete(500);
-- 31일 뒤 대상이 될 계정 수 (흉내)
select count(*) from public.list_expired_incomplete(500, null, now() + interval '31 days');
-- 미완료지만 활동 기록이 있어 지우지 않는 계정 수
select count(*) from public.users u
 where (u.onboarded_at is null or u.age_band is null)
   and (exists (select 1 from public.user_progress x where x.user_id = u.id)
     or exists (select 1 from public.user_badges x where x.user_id = u.id)
     or exists (select 1 from public.board_posts x where x.user_id = u.id)
     or exists (select 1 from public.board_comments x where x.user_id = u.id)
     or exists (select 1 from public.notices x where x.user_id = u.id)
     or exists (select 1 from public.creations x where x.user_id = u.id));
```

- [ ] 배포 뒤 `curl -H "Authorization: Bearer $CRON_SECRET" "https://pyroad.vercel.app/api/cron/purge-unconsented?dry=1"` → 응답 `incomplete`가 0(유예 중). 30일 뒤 첫 실제 파기 전날에 한 번 더 `?dry=1`로 수 확인
- 되돌리기: `supabase/rollback/00061_purge_incomplete_accounts.rollback.sql` (함수만 지움. **이미 지운 계정은 되돌릴 수 없음** — 급하면 먼저 Vercel `CRON_SECRET`을 비워 크론을 끔)

## ⛔ 배포 전 차단: 관리자 role 확인 (B119, P12-05 L1)

v1.0 앱은 관리자를 `app_metadata.role = 'admin'`으로**만** 판별합니다(`ADMIN_EMAIL` 이메일 폴백 삭제). 운영 관리자 계정에 role이 없으면 **배포하는 순간 공지 쓰기·작품 숨김이 잠깁니다** — 아래가 끝나기 전에는 배포하지 않습니다. SQL Editor(postgres).

```sql
-- 1. 확인 (읽기 전용): role = admin 인 계정 — 의도한 관리자만 나와야 함
select id, email, raw_app_meta_data ->> 'role' as role, last_sign_in_at
  from auth.users where raw_app_meta_data ->> 'role' = 'admin';
```

- [ ] 1행 이상이고 의도한 계정이면 → 다음 절로
- [ ] **0행이면** 멈추고 [v0.4 런북 "관리자 role 설정"](v0.4-runbook.md#관리자-role-설정-운영-b37)의 1번(Vercel `ADMIN_EMAIL` 값으로 계정 찾기 → 1행·`email_confirmed = true` 확인)과 2번(그 id 하나에 `{"role":"admin"}` 더하기, `begin … commit`)을 한 뒤 위 1을 다시 돌려 1행 확인
- [ ] 배포 뒤 관리자로 `/notice` → "공지 작성" 버튼이 보임. 그다음 Vercel env `ADMIN_EMAIL`은 지워도 됨(앱이 읽지 않음)
- 되돌리기: 잠겼다면 위 2번(role 부여)이 해결책(재배포 불필요 — 요청마다 Auth에서 새로 읽음)

## AI 튜터: 서버 Gemini 키 빼기 (§12-Q80, B117)

Gemini API 약관(2026-03-23 시행)이 무료·유료 모두 18세 미만 대상 서비스에서 쓰지 못하게 해 v1.0 운영은 **저장된 힌트·답변만** 씁니다(서버 AI 튜터는 v1.1에서 Claude 전환 + 법률 검토). 처리방침 v`2026-11-17`의 "Google로 이전하지 않음"과 맞추려면 **배포와 같은 날** 합니다.

1. [ ] Vercel → Project → Settings → Environment Variables에서 `GEMINI_API_KEY`를 **Production·Preview 모두 삭제**(`GEMINI_MODEL`이 있으면 같이). Development에 있어도 운영과 무관
2. [ ] 재배포(환경 변수는 새 배포부터 적용): Deployments → 최신 Production → Redeploy (v1.0 배포 자체가 이 뒤면 그 배포로 갈음)
3. [ ] **스모크**(학생 계정, 본인 API 키 없음):
   - 퀘스트 1-1 → "파이뱀에게 물어보기" → 힌트 버튼: 답 말풍선에 "저장된 답변" 꼬리표, 대화 아래 "지금은 파이뱀이 준비해 둔 답으로 도와줘요" 쪽지
   - 같은 화면 자유 질문 칸에 "print가 뭐예요?": "지금은 파이뱀이 그 질문에 바로 답하기 어려워요" + 개념 안내(저장된 답변)
   - `/settings` AI 튜터: Google Gemini 줄이 없고 "지금은 파이뱀이 준비해 둔 힌트와 답으로 도와줘요"
   - Vercel 함수 로그에 `GEMINI_API_KEY 가 없어 … (운영은 의도한 상태 …)` 경고는 정상. `[tutor] Fell back`·Gemini 오류가 없어야 함
4. [ ] (읽기 전용) 예전에 Google 키를 등록한 학생 수 — 튜터는 이 키를 쓰지 않고, 설정 화면에서 지우기만 됨:

```sql
select count(*) from public.user_api_keys where provider = 'gemini';
```
