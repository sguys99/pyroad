# v0.4 릴리즈 런북 (Phase 1 운영 적용)

> - 대상: `feat/phase1` → `main` 병합 때 운영 Supabase와 Vercel에 적용하는 사람(프로젝트 관리자)
> - 원칙: §12-Q21. 마이그레이션은 로컬과 `npm run test:rls:ci`(운영 재현 시나리오 `prod_replay`)로 검증을 마쳤고, 운영 적용은 사람이 SQL Editor에서 합니다. MCP로는 적용하지 않습니다.
> - 순서: **① 추가형 마이그레이션 → ② 앱 배포 → ③ 권한 회수 마이그레이션.** 새 앱은 ①만 적용된 DB와 ①+③ DB 모두에서 동작하고, 이전 앱은 ①만 적용된 DB에서 동작합니다.
> - 각 SQL 파일은 SQL Editor에서 `BEGIN;` + 파일 내용 + `COMMIT;`으로 감싸 실행합니다. 자기 검증 NOTICE가 기대값과 다르면 `ROLLBACK;`하고 멈춥니다.

작업이 끝날 때마다 이 문서에 단계를 추가합니다. 체크박스는 운영 적용 당일에 채웁니다.

#### 00006 확인 (P1-03)

- 적용 전 기록: `select count(*) from user_progress where status = 'completed';` (= NOTICE의 N), `select count(*) from user_progress where status = 'completed' and used_golden_key;` (= K)
- 실행 권한: 아래가 모두 `f`(service_role만 실행)
  ```sql
  select p.proname, has_function_privilege('anon', p.oid, 'EXECUTE') anon, has_function_privilege('authenticated', p.oid, 'EXECUTE') auth
    from pg_proc p join pg_namespace n on n.oid = p.pronamespace
   where n.nspname = 'public' and p.proname in ('complete_quest', 'use_golden_key', 'reset_progress', 'quest_xp', 'level_for_xp',
         'has_three_day_streak', 'decide_new_badges', 'is_stage_unlocked', 'user_progress_protect_earned_xp');
  ```
- 이전 앱 동작: 이전 앱은 새 함수·`earned_xp`를 쓰지 않으므로 퀘스트 완료·황금키·리셋이 그대로 동작합니다. 다만 ①~② 사이에 이전 앱으로 완료한 행은 `earned_xp = 0`으로 남으므로 ② 뒤에 백필을 다시 실행합니다(아래 ②).
- NOTICE의 U(total_xp가 earned_xp 합과 다른 사용자)는 참고값입니다. 예전 리셋의 과다 차감(B12)·프로젝트 황금키(P) 때문에 생기며, 그 사용자가 다음에 스테이지 리셋을 하면 합으로 맞춰집니다. 운영 데이터는 바꾸지 않습니다.
