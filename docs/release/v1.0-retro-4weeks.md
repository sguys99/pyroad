## 1. 기준선 — 배포 당일, 배포 전에 (런북 0-5)

`/admin`과 `monitoring_summary`는 v1.0 묶음(00062)과 함께 생기므로 배포 전 값은 아래 SQL로 뽑습니다. 운영 SQL Editor에 ①·② 를 그대로 붙여 실행(읽기만, 결과 한 줄씩) → 결과 표를 캡처하거나 **Export → CSV**(`baseline-B.csv`)로 두고, 아래 칸에 옮겨 적습니다. 그다음 ①의 `p` 두 줄을 기준선 A 날짜로 바꿔 한 번 더(`baseline-A.csv`).

- **기준선 A** = 계획서 §1 원래 정의 "v0.4 배포 뒤 Phase 4(랜딩 개편) 전" = 2026-11-05(분석 이벤트 시작, 결과의 `first_event_ever`로 확인) ~ 2026-11-07(Phase 4 병합 2026-11-08 전날). **2주가 아니라 3일뿐**이라 랜딩 세션이 20 미만일 수 있음(그러면 판정 불가 — 3절)
- **기준선 B** = 배포 전 28일(v0.9까지의 앱). "v1.0 출시 전후" 비교용
- 분석 이벤트는 180일 보관이라 나중에도 다시 뽑을 수는 있지만, 탈퇴한 학생의 이벤트는 지워져 값이 조금씩 줄어듭니다 — **배포 전에 적은 값이 기준**

```sql
-- ① pyRoad §1 지표 (읽기 전용, 한 문장). 기간은 p 의 두 줄만 바꿈 (KST 날짜, 양 끝 포함)
--   기준선 B(배포 당일에 실행): 그대로 = 배포 전 28일
--   기준선 A: date '2026-11-05' as d_from, date '2026-11-07' as d_to
--   결과(배포일 + 28 에 실행): (public.kst_today() - 27) as d_from, public.kst_today() as d_to  = /admin?d=28 과 같은 기간
with p as (
  select (public.kst_today() - 28) as d_from,
         (public.kst_today() - 1)  as d_to
), w as (
  select d_from, d_to,
         d_from::timestamp at time zone 'Asia/Seoul'       as t0,
         (d_to + 1)::timestamp at time zone 'Asia/Seoul'   as t1
    from p
), ev as (
  select e.* from public.analytics_events e, w where e.occurred_at >= w.t0 and e.occurred_at < w.t1
), tot as (
  select count(distinct anon_id) filter (where actor = 'user')                      as active_users,
         count(distinct anon_id)                                                    as all_ids,
         count(distinct anon_id) filter (where device in ('mobile', 'tablet'))      as mobile_ids,
         count(distinct anon_id) filter (where name = 'landing_view')               as landing_sessions,
         count(distinct anon_id) filter (where name = 'landing_cta_click')          as cta_sessions,
         count(distinct anon_id) filter (where name = 'login_success')              as login_users,
         count(distinct anon_id) filter (where name = 'login_success' and (props->>'new_user')::boolean) as signups,
         count(distinct anon_id) filter (where actor = 'user' and name in ('share_open', 'share_channel')) as sharers,
         count(distinct anon_id) filter (where source = 'client' and actor = 'user') as client_users
    from ev
), s as (   -- 가입 코호트 (D1·D7은 돌아올 날이 기간 안인 가입자만, /admin 과 같은 규칙)
  select e.anon_id, public.kst_date(min(e.occurred_at)) as d0
    from public.analytics_events e, w
   where e.name = 'login_success' and (e.props->>'new_user')::boolean
     and e.occurred_at >= (w.d_from - 7)::timestamp at time zone 'Asia/Seoul' and e.occurred_at < w.t1
   group by 1
), act as (
  select distinct anon_id, public.kst_date(occurred_at) as d from ev
   where actor = 'user' and anon_id in (select anon_id from s)
), ret as (
  select count(*) filter (where s.d0 between w.d_from - 1 and w.d_to - 1) as d1_cohort,
         count(*) filter (where s.d0 between w.d_from - 1 and w.d_to - 1
                          and exists (select 1 from act where act.anon_id = s.anon_id and act.d = s.d0 + 1)) as d1_back,
         count(*) filter (where s.d0 between w.d_from - 7 and w.d_to - 7) as d7_cohort,
         count(*) filter (where s.d0 between w.d_from - 7 and w.d_to - 7
                          and exists (select 1 from act where act.anon_id = s.anon_id and act.d = s.d0 + 7)) as d7_back
    from s, w
), ses as (  -- 30분 공백 = 새 세션, 세션마다 처음 완료한 퀘스트 수
  select anon_id, name,
         sum(case when prev is null or occurred_at - prev > interval '30 minutes' then 1 else 0 end)
           over (partition by anon_id order by occurred_at) as sn
    from (select anon_id, name, occurred_at,
                 lag(occurred_at) over (partition by anon_id order by occurred_at) as prev
            from ev where actor = 'user') x
), per as (
  select anon_id, sn, count(*) filter (where name = 'quest_complete') as c from ses group by 1, 2
), sess as (
  select count(*) as sessions, coalesce(sum(c), 0) as completes, count(*) filter (where c >= 3) as three_plus from per
), quiz as (  -- 휴대폰·태블릿에서 시작한 퀴즈 → 같은 익명 ID 완료
  select count(*) as quiz_starts, count(d.anon_id) as quiz_completes
    from (select distinct e.anon_id, e.props->>'quest_id' as q from ev e
            join public.quests qq on qq.id::text = e.props->>'quest_id' and qq.quest_type = 'quiz'
           where e.name = 'quest_start' and e.device in ('mobile', 'tablet')) st
    left join (select distinct anon_id, props->>'quest_id' as q from ev where name = 'quest_complete') d
      on d.anon_id = st.anon_id and d.q = st.q
), mot as (   -- 연출 자동 하향 (P12-04 §8)
  select count(*) as downgraded,
         count(*) filter (where exists (
           select 1 from ev u where u.name = 'motion_tier_change' and u.anon_id = m.anon_id
              and u.props->>'cause' = 'user' and u.occurred_at > m.at
              and (u.props->>'setting' = 'full' or u.props->>'to' = 'full'))) as back_to_full
    from (select anon_id, min(occurred_at) as at from ev
           where name = 'motion_tier_change' and props->>'cause' = 'measured' and actor = 'user'
           group by 1) m
)
select w.d_from, w.d_to, (select min(occurred_at) from public.analytics_events) as first_event_ever,
       tot.*, ret.*, sess.*, quiz.*, mot.*,
       round(100.0 * tot.signups      / nullif(tot.landing_sessions, 0), 1) as signup_per_landing_pct,
       round(100.0 * tot.login_users  / nullif(tot.landing_sessions, 0), 1) as login_per_landing_pct,
       round(100.0 * ret.d1_back      / nullif(ret.d1_cohort, 0), 1)        as d1_pct,
       round(100.0 * ret.d7_back      / nullif(ret.d7_cohort, 0), 1)        as d7_pct,
       round(1.0 * sess.completes     / nullif(sess.sessions, 0), 2)        as completes_per_session,
       round(100.0 * tot.mobile_ids   / nullif(tot.all_ids, 0), 1)          as mobile_pct,
       round(100.0 * quiz.quiz_completes / nullif(quiz.quiz_starts, 0), 1)  as mobile_quiz_complete_pct,
       round(100.0 * tot.sharers      / nullif(tot.active_users, 0), 1)     as share_pct
  from w, tot, ret, sess, quiz, mot;
```

```sql
-- ② 교차 확인: DB 원장 기준 (이벤트가 아님 — DNT·GPC 브라우저도 들어감, 탈퇴·파기 계정은 빠짐, 관리자 제외)
--   기간은 ①과 같게 p 한 줄만 바꿈. 기준선 B는 그대로, 결과는 (public.kst_today() - 27) as d_from, public.kst_today() as d_to
with p as (
  select (public.kst_today() - 28) as d_from, (public.kst_today() - 1) as d_to
), s as (   -- 기간 안 가입 계정 (관리자 제외)
  select u.id, public.kst_date(u.created_at) as d0
    from public.users u join auth.users a on a.id = u.id, p
   where public.kst_date(u.created_at) between p.d_from - 7 and p.d_to
     and coalesce(a.raw_app_meta_data ->> 'role', '') <> 'admin'
), att as (  -- 출석 도장 (coin_ledger attendance, ref = KST 날짜)
  select user_id, ref::date as d from public.coin_ledger where source = 'attendance'
), done as (  -- 학습한 날마다 처음 완료한 퀘스트 수 (user_progress.completed_at)
  select up.user_id, public.kst_date(up.completed_at) as d, count(*) as c
    from public.user_progress up, p
   where up.completed_at >= p.d_from::timestamp at time zone 'Asia/Seoul'
     and up.completed_at <  (p.d_to + 1)::timestamp at time zone 'Asia/Seoul'
   group by 1, 2
)
select (select count(*) from s, p where s.d0 between p.d_from - 1 and p.d_to - 1) as d1_cohort,
       (select count(*) from s, p where s.d0 between p.d_from - 1 and p.d_to - 1
          and exists (select 1 from att where att.user_id = s.id and att.d = s.d0 + 1)) as d1_stamped,
       (select count(*) from s, p where s.d0 between p.d_from - 7 and p.d_to - 7) as d7_cohort,
       (select count(*) from s, p where s.d0 between p.d_from - 7 and p.d_to - 7
          and exists (select 1 from att where att.user_id = s.id and att.d = s.d0 + 7)) as d7_stamped,
       (select count(*) from done) as learner_days,
       (select round(avg(c), 2) from done) as completes_per_learner_day,
       (select round(100.0 * count(*) filter (where c >= 3) / nullif(count(*), 0), 1) from done) as days_3plus_pct;
```

## 4. 해석 주의

- **분모 20 미만은 판정하지 않음**(`/admin`과 같은 규칙). 비율의 분모가 기준선·결과 **둘 다** 20 이상일 때만 비교. 분모와 분자를 함께 적음
- 출시 첫 주는 공지·지인 방문이 몰려 랜딩·가입이 부풀고 D7은 낮게 나오기 쉬움 — 1주차와 2~4주차를 나눠 보고 싶으면 ①을 주 단위 날짜로 네 번
- 날짜 합계 비율(랜딩 → 가입)은 사람 단위가 아님. 같은 아이가 탭을 여러 번 열면 랜딩 세션이 여러 번
- 관리자·시험 계정이 섞임(① 이벤트에는 섞이고 ②는 관리자를 뺌). 스모크용 시험 계정은 탈퇴하면 빠짐
- 4주 = 11월 말~12월 중순이면 학기말, 12월 말부터는 겨울방학이라 다음 비교 때 계절 차이를 적어 둠
- 목표 미달은 실패 판정이 아니라 v1.1 순서를 정하는 근거. 숫자 하나로 학생 행동을 단정하지 않음

-- ③ 정성 신호의 수 (내용은 보지 않음). 배포일 + 28 에 실행하면 /admin?d=28 과 같은 기간
with p as (

         (public.kst_today() + 1)::timestamp at time zone 'Asia/Seoul'  as t1
)
select (select count(*) from public.board_posts, p where created_at >= t0 and created_at < t1)            as posts,
       (select count(*) from public.board_comments, p where created_at >= t0 and created_at < t1)         as comments,
       (select count(*) from public.board_reports, p where created_at >= t0 and created_at < t1)          as board_reports,
       (select count(*) from public.board_posts, p where hidden_at >= t0 and hidden_at < t1)
     + (select count(*) from public.board_comments, p where hidden_at >= t0 and hidden_at < t1)           as board_hidden,
       (select count(*) from public.creations, p where published_at >= t0 and published_at < t1)          as gallery_published,
       (select count(*) from public.creation_reports, p where created_at >= t0 and created_at < t1)       as gallery_reports,
       (select count(*) from public.creations, p where hidden_at >= t0 and hidden_at < t1)                as gallery_hidden,
       (select count(*) from public.share_cards, p where created_at >= t0 and created_at < t1 and is_public) as public_share_cards;
