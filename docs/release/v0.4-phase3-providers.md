## 1. 미리 정한 값

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `<project-ref>` | Supabase 대시보드 → Project Settings → General의 Project ID (운영 프로젝트) | 아래 콜백 주소 |
| 서비스 주소 | `https://pyroad.vercel.app` (`src/lib/legal/meta.ts`의 `serviceUrl`) | Kakao 앱 대표 도메인, 네이버 서비스 URL, Supabase Site URL |
| **provider → Supabase 콜백** (운영) | `https://<project-ref>.supabase.co/auth/v1/callback` | Kakao 리다이렉트 URI, 네이버 Callback URL |
| provider → Supabase 콜백 (로컬 스택, 선택) | `http://127.0.0.1:54521/auth/v1/callback` (`supabase/config.toml`의 api 포트 54521) | 로컬에서 실제 앱으로 시험할 때만 (§8) |
| **Supabase → 앱 콜백** | `https://pyroad.vercel.app/auth/callback`, 개발 `http://localhost:3000/auth/callback` | Supabase Site URL·Redirect URLs (§2) |
| 개인정보처리방침 | `https://pyroad.vercel.app/privacy` (P3-14, Phase 3 배포 뒤 열림) | 네이버 검수 소명·Kakao 앱 정보 |
| 앱 이름·아이콘 | `pyRoad`, 파이뱀 아이콘(`src/app/icon.svg`를 PNG로) | 두 동의 화면에 그대로 보임 |

**콜백이 두 종류**라는 점이 가장 많이 틀립니다. Kakao·네이버 콘솔에는 **Supabase 주소**(`…supabase.co/auth/v1/callback`)를 넣고, 앱 주소(`…/auth/callback`)는 Supabase에만 넣습니다. 로그인 흐름: 앱 → Supabase → Kakao·네이버 → **Supabase 콜백** → **앱 콜백** (`/auth/callback`에서 `exchangeCodeForSession`).

아이콘 PNG 만들기(저장소에는 넣지 않음): `node -e "require('sharp')('src/app/icon.svg').resize(256,256).png().toFile('/tmp/pyroad-icon-256.png')"` (Kakao는 250KB 미만·128px 이하 권장 → `resize(128,128)`로 하나 더)

## 2. Supabase 공통 설정 (P3-02·P3-07)

- [ ] Authentication → **URL Configuration**
  - Site URL = `https://pyroad.vercel.app` (끝에 `/` 없이). Supabase는 Site URL과 **스킴·호스트·포트가 같은 주소**면 경로·쿼리와 상관없이 돌려보냅니다(GoTrue `IsRedirectURLValid`). 그래서 운영 `/auth/callback?next=…`은 Redirect URLs에 따로 넣지 않아도 됩니다
  - Redirect URLs: 운영만 쓰면 **비워 둬도 됨**. 다른 호스트(Preview 배포, 운영 Supabase를 쓰는 로컬 개발)를 허용할 때만 넣고, 쿼리(`?next=`)까지 비교하므로 `/**`로 끝냅니다. 예: `https://pyroad-git-feat-phase3-<vercel-team>.vercel.app/**` (§8, 끝나면 지움). `http://localhost:3000/**`는 로컬 앱을 **운영 Supabase에** 붙일 때만(권장하지 않음, 로컬은 로컬 스택). 와일드카드를 호스트 자리에 넓게 쓰지 않습니다(P0-03 §4.8 오픈 리다이렉트)
  - 허용 목록에 없는 주소로 시작한 로그인은 Site URL로 돌아가고, 그곳에는 PKCE 쿠키가 없어 로그인이 실패합니다(Preview 시험 때 흔한 증상)
- [ ] Authentication → **Sign In / Providers** 상단 사용자 설정 → **Allow manual linking ON** (P3-07 계정 연결, `GOTRUE_SECURITY_MANUAL_LINKING_ENABLED`). "Allow new users to sign up"은 켜 둔 그대로(B34). 토글 이름은 이번에 화면으로 확인하지 못했습니다 — 다르면 §11에 적어 주세요
- [ ] Email provider는 꺼 둔 그대로(B34)인지 확인

## 3. Kakao Developers (P3-01)

developers.kakao.com → 로그인(프로젝트 관리용 카카오 계정) → [앱] 화면. 메뉴 이름은 2025년 개편 뒤 기준입니다(앱 키가 [앱] > [플랫폼 키]·[어드민 키]로 나뉨).

1. [ ] **앱 만들기**: 앱 이름 `pyRoad`, 회사명 `유기홍`(개인 개발자, §12-Q37), 카테고리 `교육`, 앱 아이콘 = 위 128px PNG. 운영정책 동의. **비즈앱 전환은 하지 않음**(§12-Q12). 앱은 서비스당 하나만 만들고 계속 씁니다(새 앱으로 바꾸면 모든 사용자가 새로 가입한 것이 됨)
2. [ ] [앱] > [일반] > 앱 기본 정보: 앱 대표 도메인 `https://pyroad.vercel.app`
3. [ ] [앱] > [플랫폼 키] > **[REST API 키]** (앱과 함께 만들어진 기본 키)
   - [ ] **리다이렉트 URI**: `https://<project-ref>.supabase.co/auth/v1/callback` — Supabase Kakao 화면(§4)에 표시되는 Callback URL을 그대로 복사. 한 글자라도 다르면 KOE006. 로컬 시험(§8)을 할 때만 `http://127.0.0.1:54521/auth/v1/callback` 추가
   - [ ] **클라이언트 시크릿**: 새 키는 기본 **ON**. [코드 생성] → 코드를 비밀번호 관리자에 → §4 Client Secret. 켜져 있으면 토큰 요청에 필수(없으면 KOE010)
   - [ ] **호출 허용 IP 주소: 비워 둠** (채우면 Supabase 서버의 토큰 요청이 막힘)
   - [ ] REST API 키 값 → §4 Client ID (JavaScript 키·네이티브 앱 키가 아님, 틀리면 KOE101)
   - 웹 "사이트 도메인"은 REST API 방식 로그인에는 필요 없습니다(개편 뒤 도메인은 JavaScript 키의 "JavaScript SDK 도메인"으로 옮겨짐 → Phase 9)
4. [ ] [카카오 로그인] > **[사용 설정]** 상태 **ON** (OFF면 KOE004)
5. [ ] [카카오 로그인] > **[동의항목]: 아무 항목도 설정하지 않음** (§12-Q16 "식별자만"). Kakao 문서: "앱에 설정된 동의항목이 없는 경우, 카카오 로그인 동의 화면은 서비스의 앱과 사용자의 연결에 대한 안내만 포함합니다". [동의 화면 미리보기]로 개인정보 항목이 없는지 확인
   - 이 상태에서 앱은 `scope=`(빈 값)으로 요청합니다(`KAKAO_SCOPE = ''`, `src/lib/auth/socialLogin.ts`). 빈 `scope`를 Kakao가 받아 주는지는 **실제로만 확인 가능** → §9 K-1
   - **대체(K-1 실패 시에만)**: 닉네임(`profile_nickname`)을 **선택 동의**로 설정, 동의 목적 "첫 화면 별명 추천(다른 사람에게 공개하지 않음)". 그리고 Claude에게 `KAKAO_SCOPE = 'profile_nickname'`으로 바꿔 달라고 요청(코드 한 줄, 공개 필드에는 저장하지 않음). 프로필 사진·카카오계정(이메일)은 어느 경우에도 설정하지 않음
6. [ ] [카카오 로그인] > [OpenID Connect]: **OFF 유지** (내장 `kakao` provider는 쓰지 않음, `custom:kakao` 대체안을 쓸 때만)
7. [ ] [카카오 로그인] > 로그아웃 리다이렉트 URI·간편가입(카카오싱크): 설정하지 않음
8. [ ] [앱] > **[어드민 키]** (P3-16 탈퇴 시 연결 해제용)
   - [ ] **사용 가능 API: [특정 API 사용 가능] → 카카오 로그인 > "연결 해제"만** (2025-12-03 개편으로 어드민 키가 부를 수 있는 API를 고를 수 있게 됨). 다른 API는 막아 두면 키가 새도 피해가 줄어듦
   - [ ] 호출 허용 IP: 비워 둠(Vercel 서버 IP가 고정이 아님, P0-04 §7 R6)
   - [ ] 키 값 → 비밀번호 관리자 → §7 Vercel env. 브라우저·저장소·로그 금지
9. [ ] (선택) [앱] > [멤버]: 콘솔을 같이 관리할 계정을 에디터로 추가
10. Phase 9(카카오톡 공유, P9-09) 때 할 일 — 지금은 하지 않음: [앱] > [플랫폼 키] > [JavaScript 키] > JavaScript SDK 도메인 `https://pyroad.vercel.app`(+ `http://localhost:3000`), [앱] > [제품 링크 관리] > [웹 도메인]. 같은 앱을 쓰므로 공유 메시지의 앱 이름·아이콘이 로그인 동의 화면과 같음

## 4. Supabase Kakao provider (P3-02)

- [ ] Authentication → Sign In / Providers → **Kakao** → Enable
  - Kakao Client ID = **REST API 키**
  - Kakao Client Secret = 클라이언트 시크릿 코드
  - **Allow users without an email = ON** (필수. 끄면 이메일 없는 Kakao 사용자 가입이 `Error getting user email from external provider`로 실패, P0-04 §4.2)
  - 화면의 Callback URL을 복사해 §3-3 리다이렉트 URI와 글자 단위로 같은지 확인
- [ ] 저장. 요청 범위(scope)는 여기서 정하지 않습니다: Supabase 내장 Kakao는 `account_email`을 항상 요청해 일반 앱에서 KOE205가 나므로(supabase/auth#2574) 앱이 `queryParams: { scope }`로 통째로 덮어씁니다(§2.8). 그래서 §9 K-2로 실제 인가 URL을 꼭 확인합니다

## 5. 네이버 개발자센터 (P3-03)

1. [ ] **등록 계정 정하기**: 계획서는 네이버 **단체 회원** 계정을 권장합니다(등록자가 곧 관리자). 단체 계정이 없으면(개인 개발자, §12-Q37) **pyRoad 전용 개인 아이디**로 등록하고 ②에서 관리자 한 명을 더 넣습니다. 등록자는 나중에 "애플리케이션 등록자 아이디 변경 요청"으로 바꿀 수 있지만, **Client ID는 바꿀 수 없고 바꾸면 기존 네이버 사용자를 식별할 수 없습니다**(식별자가 앱마다 다름) → 앱은 하나만 만들어 계속 씁니다. 처음 등록 때 휴대폰 인증이 한 번 필요합니다
2. [ ] developers.naver.com → Application → **애플리케이션 등록**
   - 애플리케이션 이름: `pyRoad` (동의 화면에 그대로 보임, 10자 이내 권장, "네이버"·"로그인"이 들어간 이름은 반려)
   - 사용 API: **네이버 로그인**
   - 제공 정보(권한): **아무것도 고르지 않음 = "이용자 식별자"만**. 이름·이메일·별명·사진·성별·연령대·생일·휴대전화 모두 해제. 식별자만이면 검수 때 "제공 정보 활용처" 자료가 필요 없습니다(검수 가이드 3.2)
   - 로그인 오픈 API 서비스 환경: **PC 웹**과 **Mobile 웹** 둘 다 추가하고 각각
     - 서비스 URL: `https://pyroad.vercel.app` (도메인 기준, 프로토콜·포트는 구분하지 않음)
     - 네이버 로그인 Callback URL: `https://<project-ref>.supabase.co/auth/v1/callback` (최대 5개). 로컬 시험(§8)을 할 때만 `http://127.0.0.1:54521/auth/v1/callback` 추가
     - 서비스 URL(vercel.app)과 Callback 도메인(supabase.co)이 다른데, 문서에는 제한이 없고 실제 등록이 되는지는 **이 단계에서 처음 확인**됩니다(P0-03 R3) → 결과를 §9 N-0에 적기. 거절되면 멈추고 알려 주세요(대안: Supabase 커스텀 도메인 유료 애드온 또는 대안 C)
   - 로고 이미지: 위 256px PNG (네이버를 연상시키는 로고는 반려)
3. [ ] 등록 뒤 **Client ID·Client Secret**을 비밀번호 관리자에 → §6
4. [ ] 내 애플리케이션 → pyRoad → **멤버관리**: 관리자(공동 관리자 1명)·**테스터 ID** 등록. 등록자 아이디는 멤버가 아니어도 "개발 중" 상태에서 로그인됩니다. 검수 전에는 이 아이디들만 네이버로 로그인할 수 있습니다
5. [ ] **"만 14세 이상만 가입 가능"은 켜지 않음**. 이 옵션은 "서비스 약관정보"(네이버 로그인 약관 동의 대행) 메뉴에 있고, 켜면 네이버가 아는 만 14세 미만 사용자의 가입을 **막습니다**. pyRoad는 약관 동의 대행을 쓰지 않으므로 그 메뉴에 아무것도 등록하지 않습니다. 법정대리인 동의는 서비스가 직접 받습니다(P3-15)

## 6. Supabase `custom:naver` OIDC provider (P3-04)

설정값은 정해져 있습니다(§2.8): 타입 **OIDC(Auto-discovery)**, identifier `custom:naver`, issuer `https://nid.naver.com`, scope `openid`, **PKCE ON**, **email optional ON**(기본값이면 "Error getting user email from external provider"로 모든 로그인 실패, P0-03 A-7). Free 플랜은 커스텀 provider 3개까지(1개 사용).

**방법 A (권장, 값이 고정된 스크립트)** — 저장소의 [`spikes/p0-03-naver/scripts/create-naver-provider.ts`](../../spikes/p0-03-naver/scripts/create-naver-provider.ts)가 [`provider/custom-naver.provider.json`](../../spikes/p0-03-naver/provider/custom-naver.provider.json) 그대로 만들고(이미 있으면 갱신), 비밀값은 출력하지 않습니다. Node 22.18 이상.

```bash
cd spikes/p0-03-naver            # node_modules 가 없으면 npm install (supabase-js 2.101.0)
# 비밀값은 화면·셸 기록에 남지 않게 read -s 로 받음 (입력 후 Enter)
read -rs SB_KEY;  echo "service_role ok"   # Supabase → Project Settings → API Keys 의 service_role(또는 secret) 키
read -rs NV_ID;   echo "naver id ok"       # 네이버 Client ID
read -rs NV_SEC;  echo "naver secret ok"   # 네이버 Client Secret
SUPABASE_URL=https://<project-ref>.supabase.co SUPABASE_SERVICE_ROLE_KEY="$SB_KEY" \
  NAVER_CLIENT_ID="$NV_ID" NAVER_CLIENT_SECRET="$NV_SEC" \
  node scripts/create-naver-provider.ts
unset SB_KEY NV_ID NV_SEC
```

- 기대 출력: `created custom:naver issuer=https://nid.naver.com email_optional=true pkce=true` (두 번째부터는 `updated …`). 시크릿을 바꿀 때도 같은 명령
- 실패 `missing …`는 env 누락, `create failed: …`는 키·URL 확인. 출력 한 줄을 §11에 붙여 주세요(비밀값 없음)

**방법 B (대시보드)** — Authentication → Sign In / Providers → (Custom Providers) **New Provider** → **Auto-discovery (OIDC)** → Identifier `custom:naver`, 이름 `네이버`, Client ID·Client Secret, Issuer URL `https://nid.naver.com`, Scopes `openid` → email optional에 해당하는 옵션 ON, PKCE ON 확인 → **Create and enable provider**. 화면의 email optional 옵션 이름은 이번에 확인하지 못했습니다. 만든 뒤에는 방법 A 명령을 한 번 더 돌려 `email_optional=true pkce=true`를 확인하는 것을 권장합니다(같은 값으로 갱신만 됨)

- [ ] 생성 화면의 Callback URL이 §5-② 네이버 Callback URL과 같은지 확인
- 앱 코드는 이미 `signInWithOAuth({ provider: 'custom:naver' })` + 기존 `/auth/callback`입니다(P1-14). 네이버 앱으로 자동로그인 `appscheme=true`·공용 기기 `prompt=login`은 P3-09 코드가 `queryParams`로 붙입니다

## 7. Vercel env (P3-16)

- [ ] Vercel → Settings → Environment Variables → `KAKAO_ADMIN_KEY` = §3-8 어드민 키, **Production만**, **Sensitive**. 등록 뒤 재배포해야 적용(코드가 읽는 것은 P3-16 배포부터라 미리 넣어도 무해)
- Preview에는 넣지 않습니다. 일반 앱은 테스트 앱을 만들 수 없어(테스트 앱은 비즈앱 전용) 키가 하나뿐이고, Preview에서 탈퇴를 시험하면 운영 키로 실제 연결이 끊깁니다. 키가 없으면 P3-16 코드는 연결 해제를 건너뛰고 기록만 남기게 만듭니다
- Kakao Client ID·Secret은 Vercel env에 넣지 않습니다(Supabase가 처리, `.env.example` 3절). 네이버 Client ID·Secret은 로그인에는 쓰지 않고 탈퇴 때 토큰 폐기에만 씁니다(아래)
- [ ] **네이버 연동 해제 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`** (P3-16, `src/lib/auth/providerUnlink.ts`): §5의 네이버 Client ID·Secret(Supabase `custom:naver`에 넣은 것과 같은 값)을 **Production**에 **Sensitive**로. 탈퇴 직전 네이버 재인증으로 받은 토큰을 `POST https://nid.naver.com/oauth2.0/revoke`로 폐기해 네이버 "연결된 서비스"에서 pyRoad를 지웁니다(토큰은 저장하지 않음). 없으면 폐기를 건너뛰고 탈퇴 화면이 "네이버 → 내정보 → 이력관리 → 연결된 서비스 관리에서 직접 끊기"를 안내합니다. Preview에 넣어도 되지만 그 경우 테스터 계정의 실제 연동이 끊깁니다. 네이버 "연결끊기 Callback URL"(사용자가 네이버에서 먼저 끊었을 때 알림)은 아직 받지 않습니다(후속)
- [ ] **로그인 버튼 숨기기 `NEXT_PUBLIC_LOGIN_PROVIDERS`** (P3-09, `src/lib/auth/enabledProviders.ts`): 네이버 검수(§5)가 끝나기 전에 배포하면 Production·Preview에 `kakao,google`을 넣어 네이버 버튼만 숨깁니다(검수 전에는 관리자·테스터 ID만 로그인되어 일반 사용자는 실패 화면만 봄). 검수가 끝나면 변수를 지우고(비우면 세 개 모두) 재배포합니다. 공개 값이라 빌드에 들어가므로 바꿀 때마다 재배포가 필요하고, 순서는 env가 아니라 화면 규칙(카카오톡 인앱이면 카카오 먼저 → 최근에 쓴 수단 → 카카오·네이버·Google)이 정합니다. 알아볼 수 없는 값만 있으면 오타로 버튼이 모두 사라지지 않게 세 개 모두 보입니다. 숨겨도 Supabase provider 설정과 이미 연결된 계정은 그대로라, 테스터는 숨긴 상태에서도 Preview에 변수를 비워 두고 네이버를 시험할 수 있습니다

## 9. 스모크 테스트 (결과 칸을 채워 주세요)

공통 방법
- **인가 URL 보기**: PC Chrome DevTools → Network → "Preserve log" 체크 → 로그인 버튼 클릭 → 목록에서 `kauth.kakao.com/oauth/authorize` 또는 `nid.naver.com/oauth2/authorize` 요청을 골라 Headers의 Request URL(또는 그 앞 `…supabase.co/auth/v1/authorize` 응답의 `Location`)에서 `scope` 값을 봅니다
- **DB 확인(읽기 전용)**: Supabase SQL Editor에서

  ```sql
  select i.provider, u.email is null as no_email, u.created_at, u.last_sign_in_at,
         (select array_agg(k) from jsonb_object_keys(u.raw_user_meta_data) k) as meta_keys,
         p.display_name
    from auth.identities i
    join auth.users u on u.id = i.user_id
    left join public.users p on p.id = u.id
   where i.provider in ('kakao', 'custom:naver')
   order by u.created_at desc limit 10;
  ```

  식별자(`provider_id`)·이메일 값은 Claude에게 보내지 않습니다. 열 이름·참/거짓·개수만 적어 주세요

| N-11 | 탈퇴 = 연동 해제 (P3-16, Production에 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`) | 탈퇴하기 → "네이버 연결도 끊을까요?" → 네이버 로그인 → 프로필로 돌아와 "네이버 연결을 끊었어요" + 탈퇴 확인 → 탈퇴 뒤 네이버 → 내정보 → 이력관리 → 연결된 서비스 관리에서 pyRoad가 사라짐. 실패하면(Vercel 로그 `naver unlink http_<상태>`) OIDC 토큰이 `/oauth2.0/revoke`에서 거절되는지 확인 → discovery의 `/oauth2/revoke`로 바꿔 시험(`NAVER_REVOKE_URL`) | |

N-10 방법(선택): 로그인 직후 DevTools → Application → Cookies에서 `sb-<project-ref>-auth-token`(`.0`, `.1`로 나뉠 수 있음, 값이 `base64-`로 시작) 값을 이어 붙여 base64 디코드 → JSON의 `provider_token`. 터미널에서 `curl -s -H "Authorization: Bearer <provider_token>" https://openapi.naver.com/v1/nid/me`의 `response.id`와 SQL `select provider_id from auth.identities where provider = 'custom:naver' order by created_at desc limit 1`이 같은지만 봅니다. 쿠키에 `provider_token`이 없거나 프로필 API가 OIDC 토큰을 거절하면 "확인 불가"로 적습니다. 토큰과 식별자는 어디에도 붙여 넣지 않습니다.

시험이 끝나면: 시험 계정은 앱의 탈퇴(P3-16 배포 전이면 Supabase Authentication → Users에서 삭제, 배포 뒤에는 K-10·N-11로 연결이 같이 끊겼는지 확인) 후, 남아 있으면 카카오는 카카오톡 → 설정 → 카카오계정 → 연결된 서비스 관리에서 pyRoad 연결 끊기, 네이버는 네이버 → 내정보 → 이력관리 → 연결된 서비스 관리에서 철회. Preview용 Redirect URL 제거.
