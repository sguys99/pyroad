# v0.7 릴리즈 런북 (Phase 9 운영 적용)

> - 대상: `feat/phase9` → `main` 병합 때 운영 Supabase와 Vercel에 적용하는 사람(프로젝트 관리자)
> - v0.7 = Phase 9(§10). 태그 `v0.7`은 Phase 9를 병합한 뒤 `main`에서 붙입니다
> - 원칙은 [v0.6 런북](v0.6-runbook.md)과 같습니다(§12-Q21): 마이그레이션은 로컬과 `npm run test:rls:ci`(운영 재현 `prod_replay`)로 검증했고, 운영 적용은 사람이 SQL Editor에서 합니다. MCP로는 적용하지 않습니다. 순서는 **① 추가형 마이그레이션 → ② 병합·배포 → ③ 권한 회수 마이그레이션**(있을 때만)
> - **SQL은 `release-sql` 묶음 파일로 붙여 넣습니다**(B39): `node scripts/release/build-release-sql.mjs --release v0.7-phase9` → `release-sql/v0.7-phase9/`(git 제외). 파일 안에 `BEGIN;`/`COMMIT;`이 있어 전체를 그대로 붙여 실행하고, 하나라도 실패하면 전체가 되돌려집니다. CRLF 리허설: `RLS_CRLF=1 npm run test:rls:ci`

체크박스는 운영 적용 당일에 채웁니다.

배포 뒤(②) 확인: 로그인해 `POST /api/share-cards {"kind":"levelup"}` → 응답 `imageUrl`을 열면 1200×630 PNG, 응답 헤더 `vercel-cache-tag: share-card-<id>`·`vercel-cdn-cache-control: public, max-age=…`(90일 이하). 두 번째 요청은 `x-vercel-cache: HIT`. Vercel 함수 로그에 `[share-card]` 오류가 없어야 함. 함수 크기는 빌드 로그 `/api/share-cards/[id]/image` ≈ 7MB(폰트 3개 포함).
