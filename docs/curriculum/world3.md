## 1. 3월드의 학습 목표

1월드는 "한 줄씩 명령하기", 2월드는 "여러 값을 묶고 틀린 곳을 고치기"였습니다. 3월드는 **"사람이 쓰고, 보고, 노는 작품을 처음부터 끝까지 만드는"** 단계입니다.

1. 거북이에게 반복과 함수로 명령해 도형·무늬·장면을 그릴 수 있다.
2. `input()`으로 사용자와 대화하고, 들어온 글자를 숫자로 바꾸고, 잘못 들어오면 다시 물을 수 있다.
3. 사용자의 선택에 따라 다르게 흘러가는 이야기·퀴즈 프로그램을 만들 수 있다.
4. `class`로 "설계도"를 만들어 상태(배고픔·기분)와 행동(메서드)을 한데 묶을 수 있다(맛보기).
5. 데이터를 세고 평균을 내고, 막대그래프로 보여 주고, 결론을 한 문장으로 말할 수 있다.
6. 정해진 시간 동안 도는 게임 루프에서 키 입력·충돌·점수를 다룰 수 있다.
7. 자기 아이디어를 작은 기능 3개로 나눠 기획하고, 만들고, 고치고, 친구에게 보여 줄 수 있다.

### 이야기 줄거리

"코드 선장"이 된 모험가가 배를 대고 내린 곳은 **메이커 시티**. 거리마다 작업실이 있는데, 버그버그가 작업실 설계도를 몽땅 뒤섞어 놓아 도시의 기계와 그림이 멈춰 버렸어요. 모험가는 작업실을 하나씩 돌며 **직접 만든 작품**으로 작업실을 다시 움직이게 하고, 마지막 "메이커 박람회"에서 자기만의 작품을 전시합니다. 버그버그는 끝에서 거대한 로봇을 만들어 마지막 시험을 냅니다.

## 3. 왜 "스테이지 = 준비 퀘스트 + 대형 프로젝트 1개"인가 (제안 A)

계획서 초안은 "6~7개 대형 프로젝트"만 적었습니다. 두 모양을 견줬습니다.

| | (가) 3-x 하나 = 거대한 프로젝트 퀘스트 하나 (10단계 이상) | (나) **3-x 하나 = 스테이지**: 준비 퀘스트 3~4 + 프로젝트 1(5단계) + 퀴즈 2 + 보스 |
|---|---|---|
| 새 개념 연습 | 프로젝트 단계 안에서 처음 배우고 바로 합쳐야 함 → 3학년이 막힘(2월드 2-F A 학생 35분) | 준비 퀘스트에서 하나씩 익힌 뒤 프로젝트에서 합침 |
| 보상 간격 | XP·별이 프로젝트 끝에 한 번(1~2시간 뒤) | 10~15분마다 별, 지도 노드가 차오름 |
| 기존 시스템 | 지도·보스·보물상자·"스테이지마다 모바일 퀘스트" 완료 기준과 안 맞음 | 1·2월드와 같은 스테이지·보스·상자 규칙 그대로 (엔진 변경 없음) |
| 갤러리 | 출품 시점이 하나 | 프로젝트마다 하나 = 출품 7번 |

→ **(나)를 고릅니다.** 프로젝트는 스테이지 맨 뒤(보스 바로 앞) 한 개, 5단계(3-F는 4단계). 2월드 2-F 프로젝트(5단계, 30~35분)보다 조금 큰 45~60분 크기입니다. 준비 퀘스트는 **각각 프로젝트의 한 조각**을 미리 만들어 보는 것이라, 프로젝트 단계 힌트가 "준비 퀘스트 #3에서 만든 그 함수!"를 가리킬 수 있습니다.

### 프로젝트 쓰기 두 방식 (제안 B)

프로젝트 단계 k의 화면 코드는 **(k−1 단계 정답 + k 단계 시작 코드)**입니다(content/README.md). 그래서 단계마다 코드가 어떻게 자라는지를 미리 정해 둡니다.

| 방식 | 언제 | 규칙 |
|---|---|---|
| **덧붙이기** | 그림이 자라는 프로젝트(3-1 마을, 3-5 그래프) | 새 코드는 맨 아래에 붙음. 앞 단계 그림이 캔버스에 남으므로 그림 규칙은 "이것이 **있다**"로만 씀("이것만 있다" 금지). `def`와 그 함수를 부르는 줄은 **같은 단계**에서 함께 |
| **고쳐 나가기 + 자리표 주석** | 대화형 프로그램(3-2·3-3·3-4·3-6) | 시작 코드는 비우거나 몇 줄. 앞 단계 정답에 `# (3단계) 여기서 하트를 줄여요` 같은 **자리표 주석**을 미리 넣어 고칠 곳을 알려 줌. 큰 구조 바꾸기(리팩터링)는 하지 않음 |
| **설계도 자리 (`pass`)** | `class`를 쓰는 3-4 | 1단계 정답에 2단계 메서드를 `def feed(self):` + `pass  # 2단계에서 채워요`로 미리 둠. 클래스 안에 코드를 "덧붙일" 수 없기 때문 |

- **L4 교훈(2월드 플레이테스트)**: `code_check`는 **그 단계에서 학생이 새로 써야 하는 글자**로 고릅니다. 앞 단계 정답·시작 코드에 이미 있는 글자(`for`, 함수 이름 등)는 검사 효과가 없습니다. 아래 표의 코드⊃ 칸은 이 원칙으로 골랐고, 최종 글자는 P11-12~14에서 `test:content`의 시작 코드 불합격 검사로 확인합니다.
- **입력이 쌓임**: 고쳐 나가기 방식에서 앞 단계의 `input()`도 그대로 실행되므로, 단계 k의 시나리오 `inputs`에는 앞 단계 입력까지 차례로 넣습니다.

**시험 손님 채점 (제안 C)** — 입력 퀘스트를 무엇으로 채점할지:

- (가) 학생이 직접 플레이한 실행의 출력으로 채점: 아이가 무엇을 입력했는지에 따라 결과가 달라 규칙이 아주 넓어야 하고, 한 갈래만 해 보고 통과하면 다른 갈래 버그를 못 잡음.
- (나) **"채점" 버튼은 퀘스트의 시험 입력(`scenarios[].inputs`)으로 학생 코드를 자동으로 여러 번 실행**하고, 그 대화를 채팅처럼 보여 줌("별똥이 손님이 1번 문을 골라 볼게요"). 입력값은 공개(정답이 아님), 시나리오별 규칙은 서버만. 서버는 시나리오별 stdout을 다시 채점(§2.3, stdout 재채점과 같은 신뢰 수준).
- **(나)를 추천합니다.** CI(`test:content`)와 앱이 같은 시험을 쓰고, `setStdin` 큐라 **JSPI·SW가 없는 기기(iOS 26 이하 인앱)에서도 채점은 됩니다**(플레이만 "Safari로 열기"). 1월드 7-3을 `input()` 버전으로 바꿔도(P11-15) 그런 기기의 학생이 1월드를 못 깨는 일이 없습니다. 그림 퀘스트도 같은 모양으로: 채점 실행의 명령 스트림을 서버로 보내 다시 검사.

## 11. P11-15 메모: 1월드 숫자 맞추기를 진짜 `input()`으로

- **대상**: `content/worlds/python-island/07-project-kingdom/03-number-guessing-game.yaml` (id `b1000000-…-000000000022`, 200 XP). 계획서의 "7-1"은 7단계의 이 퀘스트(파일 순서 3번째)입니다.
- **바꿀 것**

| 단계 | 지금 | 바꾼 뒤 | 채점 |
|---|---|---|---|
| 1 | `secret = random.randint(1, 10)` + `print(secret)` | 그대로 (비밀 숫자 확인용) | 그대로 `code_check random.randint` |
| 2 | `guess = int(random.randint(1, 10))` ("Pyodide에서는 random으로 대체") | `guess = int(input("1~10 숫자를 맞혀 봐요: "))`. 체크리스트에 "비밀 숫자를 보여 주는 줄은 `#`로 숨겨요"(채점 밖, 주석 = 실행 안 함 복습) | 시나리오[5]⊃`추측: 5` + 코드⊃`input(` |
| 3 | 무작위 추측으로 세 갈래 중 하나 (`contains_any`) | 입력 한 번으로 세 갈래 중 하나 | 시나리오[5]⊃하나[커요, 작아요, 정답] + 코드⊃`elif` |
| 4 | `while`에서 무작위로 다시 추측 | `while` 안에서 다시 `input` | 시나리오[1, 2, …, 10]⊃`정답` + 시나리오[10, 9, …, 1]⊃`정답` + 코드⊃`while` |
| 5 | 시도 횟수 | 그대로 | 4단계 시나리오 2개 ⊃ `번 만에 맞췄어요` |

- **시드 없이 결정적 (제안 D)**: 1부터 10까지 차례로 넣으면 비밀 숫자가 무엇이든 10번 안에 맞히고 끝납니다. 그래서 `seed`가 필요 없고, `randint` 대신 `choice(range(1, 11))`처럼 다르게 뽑는 맞는 답도 통과합니다(B09 걱정 없음). 반대로 `guess`를 다시 안 받는 버그는 무한 루프 대신 11번째 입력에서 `EOFError`로 떨어집니다. 범위 1~10은 그대로 둡니다(1~100이면 시험 입력이 100개).
- **1월드에서 하지 않는 것**: 숫자가 아닌 입력 처리(`try`는 2-5에서 배움). 힌트에 "숫자만 입력해요", 글자를 넣으면 기존 오류 쪽지가 `ValueError`를 설명.
- **같이 고칠 곳**: 2단계 `fallback_text`에 `input()` 첫 소개(1월드 학생에게는 처음), 1월드 튜터에도 용어 `input` 한 줄(지금 용어집은 2월드 이상, P10-08), `expected_output_hint`·`example_output`에 입력 말풍선 예시. 이미 끝낸 학생의 완료·XP는 그대로(새 제출만 새 규칙).
- **의존**: P11-01(플레이), P11-05(시나리오별 기대 출력), 제안 C(입력 채널 없는 기기의 채점). C를 채택하지 않으면 iOS 26 이하 인앱 학생이 1월드 7단계를 깰 수 없으니, 그때는 "입력 채널 없음 → 시험 손님만 실행"을 따로 만들어야 합니다.
